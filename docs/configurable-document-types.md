# Настраиваемые виды документов и компаньоны

Граница приложений и модель связей: [architecture-documents-vs-plans.md](architecture-documents-vs-plans.md).

В интерфейсе очередной вариант одного документа называется **редакцией**. Учебные планы за разные годы — разные документы. В коде сущность по-прежнему `DocumentVersion`.

---

## Вывод

Виду без собственного разбора файла достаточно записи в `settings.DOCUMENT_TYPES` и перезапуска. Виду с парсером нужен ключ экстрактора в коде.

Компаньоны — отдельные документы со связью `DocumentRelation`. Слоты и профиль жизненного цикла задаются в реестре видов. Конструктор в админке без перезапуска — следующая версия; граница поставщика профиля уже заложена.

---

## Спецификация вида

Модуль `documents/document_types.py`:

| Поле | Смысл |
|------|--------|
| `code` | Значение `Document.document_type` |
| `label` | Подпись в интерфейсе |
| `file_extensions` | Ожидаемые расширения |
| `naming_strategy` | Ключ стратегии имени: `plx` или `filename` |
| `metadata_extractor` | Ключ разбора файла или пусто |
| `companions` | Список слотов компаньонов у этого вида (может быть пустым) |
| `lifecycle` | Необязательный профиль жизненного цикла; пусто → профиль учебного плана |

### Слот компаньона (`companions`)

| Поле | Пример |
|------|--------|
| `code` | `printed_form` — вид документа-компаньона |
| `anchor` | `document` — ко всей цепочке; `edition` — к одной редакции |
| `cardinality` | `0..1`, `0..n`, `1` |
| `generator` | Ключ авточерновика или пусто |

### Профиль жизненного цикла

| Поле | Смысл |
|------|--------|
| `statuses` | Список `{code, label}` |
| `transitions` | Список `{action, label, from, to, roles, requires_comment}` |
| `create_roles` | Кто создаёт документ и первую редакцию |
| `update_roles` | Кто загружает новую редакцию и перепривязывает |
| `view_roles` | Кто видит и скачивает |

Код статуса уникален внутри профиля. Подпись на экране берётся из профиля вида редакции. Корзина / восстановление / окончательное удаление — системные, не из профиля.

Рантайм читает профиль через поставщик (`documents.lifecycle`). Реализация этой версии — настройки. Следующая — таблицы в БД; карточка и сервис перехода не меняются.

## Печатная форма (первый слот)

В реестре:

- вид `printed_form`: расширения `.pdf` / `.xlsx`, имя по файлу, профиль «Черновик» → «Утверждён»;
- у `plx` слот `companions`: `code=printed_form`, `anchor=edition`, `cardinality=0..1`.

Права: создавать / обновлять / перепривязывать / утверждать — рецензент учебного отдела и администратор. Разработчик УП — только просмотр и скачивание. Глобальный `ROLE_CAN_UPLOAD` (загрузка PLX) на учебный отдел не расширяется.

## Связь и интерфейс

`DocumentRelation`: `source_document` (компаньон), `target_document` (главный), `target_version` (для якоря `edition`), `slot_code`, `is_current`.

Сервис: привязка, перенос на другую редакцию того же главного, запрет цикла, снятие связи, список сирот.

На карточке главного — блок слотов: файл, «Загрузить», «Привязать существующий» (для `edition`), скачивание по праву просмотра.

На карточке компаньона — «Относится к: …».

Срез списка по виду документа. Фильтр «без главного» и массовое удаление сирот.

При удалении главного — вопрос про прямых зависимых; по умолчанию только снять связи.
