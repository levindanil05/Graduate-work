# Настраиваемые виды документов и связанные документы

Оценка реализуемости и первый шаг, который уже в коде.  
Граница приложений и концепция связей: [architecture-documents-vs-plans.md](architecture-documents-vs-plans.md).

В интерфейсе очередной вариант одного документа называется **редакцией** (то же понятие, что ревизия). Учебные планы за разные годы — разные документы. В коде сущность по-прежнему `DocumentVersion`.

---

## Вывод

Реализуемо поэтапно.

Виду, которому достаточно «файл + редакции + общее согласование + имя файла», не нужен новый код: запись в `settings.DOCUMENT_TYPES` и перезапуск. Позже ту же запись можно будет править в админке.

Виду с собственным разбором файла нужен небольшой плагин в коде (экстрактор), но не новое приложение.

Связанные документы (ОПОП, читаемая выгрузка) в этом шаге **не** реализованы: нет таблицы связей и нет блока на карточке.

## Что уже сделано (этап 0)

Модуль `documents/document_types.py`:

| Поле спецификации | Смысл |
|-------------------|--------|
| `code` | Значение `Document.document_type` |
| `label` | Подпись в интерфейсе |
| `file_extensions` | Ожидаемые расширения (для следующих шагов UI) |
| `naming_strategy` | Ключ стратегии имени: `plx` или `filename` |
| `metadata_extractor` | Ключ разбора файла или пусто |

По умолчанию в реестре `plx` и `generic` — поведение учебных планов не меняется. Поле `document_type` больше не ограничено жёстким списком choices: допустимый код проверяется по реестру. Неизвестный вид отклоняется при загрузке.

Константы `DocumentType.PLX` и `DocumentType.GENERIC` остаются для существующего кода. Сравнение со строкой кода по-прежнему верно (`"plx" == DocumentType.PLX`).

## Что мешает сделать всё сразу

- Списки, фильтры и загрузка учебных планов живут в `plans` и завязаны на тип `plx` (`plans/querysets.py`, `plans/document_views.py`, `documents/querysets.py`).
- Каноническое имя и разбор PLX — отдельные ветки в `documents/services.py`.
- Отгрузка в резервное облако строит путь через `PlacementPolicy` только для PLX (`external_sync/hooks.py`).
- Жизненный цикл один на все виды. Статус «Согласован УО» и смысл «Утверждён» (печатная форма с печатью ректора, отгрузка и архивация прежней редакции) сейчас общие.
- `documents/relationship_map.py` проверяет только внутренние ссылки (редакция принадлежит документу, обсуждение — редакции). Это не граф связанных документов.
- Модели `DocumentRelation` нет.

## Связанные документы: предлагаемая модель

Связанный документ — обычные `Document` и `DocumentVersion` со своим `document_type`. Файловое хранилище не меняется.

Связь — отдельная таблица:

| Поле | Смысл |
|------|--------|
| `source_document` | Связанный документ (ОПОП, выгрузка) |
| `target_document` | Базовый документ (учебный план), всегда заполнен |
| `target_version` | Редакция-якорь. Пусто, если связь на весь документ |
| `kind` | Вид связи |
| `is_current` | Какая из нескольких связей этого вида сейчас действующая |

Настройка задаётся у **базового** вида (например, `plx`), списком `relations` в его спецификации:

| Поле настройки | Пример |
|----------------|--------|
| `kind` | `companion_of_document`, `derived_from_version` |
| вид связанного документа | `opop`, `plx_readable_export` |
| якорь | `document` — ко всей цепочке (ОПОП); `edition` — к одной редакции (читаемая выгрузка) |
| кратность | `0..1`, `0..n`, `1` |
| при утверждении базовой редакции | «пометить устаревшей» или «ничего» |

Кратность проверяет сервис в момент привязки. Удаление базового документа не удаляет связанные молча: связь снимается, пользователь видит предупреждение.

### Интерфейс

На карточке базового документа — блок «Связанные документы» по видам связи: список, «Загрузить», «Привязать существующий», «Отвязать».

На карточке связанного документа — строка «Относится к: …». Загрузка со страницы базового документа сразу создаёт связь.

## Дальнейшие этапы

1. Модель `DocumentRelation`, сервис привязки и поле `relations` в спецификации вида.
2. Блок на карточке документа.
3. Хук: утверждена новая редакция базового документа — производные связи с якорем «редакция» помечаются устаревшими. Сопутствующие (якорь «документ») не трогаются. Отгрузка в резервное облако по-прежнему только при статусе «Утверждён».
4. Общий список и загрузка для видов, которые не являются учебным планом, вне приложения `plans`.
5. Свой профиль жизненного цикла у вида, если общему циклу он не подходит.
6. Правка реестра видов в админке (запись в базе вместо `settings.DOCUMENT_TYPES`).
